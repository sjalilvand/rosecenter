🧩 مستندات REST API — نسخه v1

این API به سامانه‌های خارجی (بیمه‌ها، سازمان‌ها، وب‌سایت‌های همکار و...) اجازه می‌دهد برای کاربران خود درخواست مشاوره ثبت کنند و وضعیت درخواست را استعلام کنند. کلیدها را از صفحه کلیدهای API بسازید.

۱) احراز هویت

در تمام درخواست‌ها یکی از دو هدر زیر را ارسال کنید:

X-API-Key: rc_xxxxxxxxxxxxxxxxxxxxxxxx
Authorization: Bearer rc_xxxxxxxxxxxxxxxxxxxxxxxx

۲) بررسی سلامت اتصال

GET /api/v1/ping
→ { "ok": true, "service": "rosecenter-api", "version": "v1", "system": "نام سامانه شما" }

۳) ثبت درخواست مشاوره

POST /api/v1/consultations
Content-Type: application/json
X-API-Key: rc_xxxx...

{
  "full_name": "سارا محمدی",        (الزامی)
  "phone": "09123456789",          (الزامی — 10 تا 11 رقم)
  "service_type": "زوج‌درمانی",     (الزامی — از فهرست مقادیر مجاز)
  "center": "تهران",               (اختیاری)
  "note": "توضیحات کاربر"          (اختیاری)
}

→ 201 { "ok": true, "tracking_code": "RC-XXXXXXXX", "status": "در انتظار بررسی" }

مقادیر مجاز service_type: {% for t in THERAPY_TYPES %}{{ t }} {% endfor %}

۴) فهرست درخواست‌ها

GET /api/v1/consultations?limit=20&offset=0&status=در انتظار بررسی
→ { "ok": true, "total": 42, "limit": 20, "offset": 0, "items": [ ... ] }

۵) استعلام وضعیت با کد پیگیری

GET /api/v1/consultations/RC-XXXXXXXX
→ { "ok": true, "item": { "tracking_code": "RC-XXXXXXXX", "status": "در حال بررسی", ... } }

۶) متادیتا (نوع‌های درمان و مراکز فعال)

GET /api/v1/meta/services
→ { "ok": true, "service_types": [...], "statuses": [...], "centers": [...] }

۷) کدهای خطا

کد HTTPerror.codeتوضیح
401missing_api_keyهدر کلید ارسال نشده است
401invalid_api_keyکلید نامعتبر است
403inactive_api_keyکلید غیرفعال شده است
400missing_full_name / invalid_phone / missing_service_type / invalid_service_typeخطای اعتبارسنجی داده
404not_foundکد پیگیری یافت نشد

curl -X POST "{{ request.host_url }}api/v1/consultations" \

  -H "X-API-Key: rc_xxxxxxxxxxxxxxxxxxxxxxxx" \
  -d '{"full_name":"علی رضایی","phone":"09123456789","service_type":"درمان فردی","center":"تهران"}'
